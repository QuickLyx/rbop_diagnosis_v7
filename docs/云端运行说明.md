## 1. 仓库自带什么（clone 后即可训练，不需要 21GB 原始数据）

训练和评估**只读特征缓存**，不读原始信号。仓库已带齐：

| 内容 | 大小 | 说明 |
| --- | ---: | --- |
| `outputs/features/cwru.npy` + `.json` | 67 MB | 源域 logspec512 缓存（153 文件 / 306 记录 / 68,516 窗），带口径版本 `v7_logspec512_12k_drop_ka08_v1` |
| `outputs/features/paderborn.npy.part-00/01/02` | 90+90+54 MB | **PU 缓存分卷**（整文件 234 MB 超 GitHub 100MB 单文件限制，故分卷入库）；首次 `check` 自动合并成 `paderborn.npy` |
| `outputs/features/checksums.md5` | <1 KB | 两个 `.npy` 的 md5；`check` 时强校验 |
| `outputs/features/paderborn.json` | 1.4 MB | PU 缓存元数据（2,559 记录 / 116 主单元 / 216,350 窗区间） |
| `outputs/selection/selection.json` | 46 KB | **冻结标注池**（k=19，K19/K38/K116 嵌套池），只读不改 |
| `outputs/data/dropped_recordings.json` | <1 KB | 官方截断文件 `KA08_2` 的整条丢弃记录（D12 凭据） |
| 代码 + `scripts/run_cloud.sh` + `configs/` + `docs/` + `tests/` | <1 MB | — |

**不入库**：`Data/paderborn/_raw/`（5.0 GiB）与 `extracted/`（21 GiB）——云端不需要，特征缓存已覆盖全部训练/评估所需窗口。PU 枚举测试使用临时文件名，不依赖原始数据；缓存中保留的 Windows 路径只作记录凭据，读取端兼容两种分隔符，不访问原路径。

仓库合计约 **305 MB**，最大单文件 90 MB，全部低于 GitHub 100MB 单文件限制。

## 2. 环境

```bash
python3 -V                                        # 建议 Python 3.12 或 3.13；不保证后续版本兼容 torch 2.6
python3 -m pip install -r requirements.txt         # 固定版本见 requirements.txt
# 若镜像自带的是 CPU 版 torch，强制替换，避免“版本已满足”而仍保留 CPU 包：
python3 -m pip install --force-reinstall torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
python3 -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

只需 torch / numpy / scipy / scikit-learn 四个包（评估 CSV 走标准库，无 pandas）。

> 版本注：scikit-learn 只影响 `selection.py`（选标已冻结，云端**不重跑**）；scipy 影响 logspec 特征（缓存已随仓库带齐并强校验，云端**不重算**）。`check` 里的单元测试会在开训前把版本兼容性实际验证一遍。

## 3. v6 依赖怎么带（与 v6 说明的关键差异）

v7 的 `_v6.py` 隔离加载 `../rbop_diagnosis_v6/` 下的 3 个模块（`dataset.py`、`model.py`、`preprocessing.py`），CWRU 数据根也指到 `../rbop_diagnosis_v6/Data/`（`datasets/cwru.py`）。云端 clone v7 后必须补齐这个同级目录：

```bash
git clone <你的v7仓库地址> rbop_diagnosis_v7 && cd rbop_diagnosis_v7
git clone https://github.com/QuickLyx/rbop_diagnosis_v6.git ../rbop_diagnosis_v6
```

- v6 仓库已含 `Data/`（657 MB，161 个 `.mat`）随仓库分发，clone 即可，无需另传。
- **两个目录必须同级**（`rbop_diagnosis_v7/` 旁边是 `rbop_diagnosis_v6/`），否则 `check` 第 2 步报"缺少只读 v6 仓库"退出。

## 4. 首次运行：`check` 一条命令自检

```bash
bash scripts/run_cloud.sh check
```

依次做五件事（任一失败立刻停，不带病开训）：

1. CUDA 可用性 + GPU 名字；
2. `../rbop_diagnosis_v6/model.py` 存在；
3. 特征缓存齐全 + **md5 强校验**（分卷自动合并）；
4. joint dry-run：完整校验冻结配置 / selection / 双缓存 / 153×116 口径（不建模型、不训练）；
5. 全部无训练单元测试（含跨平台路径与假任务 shell 回归，提前暴露环境和控制流程问题）。测试日志保存在 `logs/cloud_tests.log`。

通过后打印 `自检通过：CUDA / v6 目录 / 特征缓存 / selection / 冻结口径 全部就绪`。

## 5. 单格试跑，再跑全批

先跑一个 joint 和对应两份只读评估，确认模型链路、耗时与显存。以下命令会真实训练 30 轮；单格完成后，全批会跳过这些已完成产物：

```bash
PAR=1 bash scripts/run_cloud.sh _cell joint 0 0
PAR=1 bash scripts/run_cloud.sh _evalcell joint_f0_s0 paderborn
PAR=1 bash scripts/run_cloud.sh _evalcell joint_f0_s0 cwru
```

确认后开全批；`PAR` 必须是正整数，先从 2 起步，按实际资源使用调整：

```bash
mkdir -p logs
PAR=2 nohup bash scripts/run_cloud.sh all > logs/cloud_all.log 2>&1 &
tail -f logs/cloud_all.log        # 或另开终端：bash scripts/run_cloud.sh status
```

`all` = `check` + `train` + `eval`。单格失败不会中断**同阶段**其他格，失败名单在 `logs/failed_train.txt` / `logs/failed_eval.txt`；阶段结束返回非零并停止后续阶段。CUDA、自检或任务分发失败也会返回非零，不能按成功继续。

重跑只跳过由本脚本成功运行、带 `.complete` 标记且产物齐全的格：训练需 `config.json`、`split.json`、`last.pt`、`best.pt`、`history.csv`；评估需四份报告。仅有中间轮 `last.pt`、部分 `metrics.json`、缺文件或无标记均不算完成。残留目录挪到 `<cell>_failed_<时间戳>_<进程号>` 留现场，再**从头重跑该格**，不是从中断轮接着训。不要自行补写 `.complete`。

同一工作区只运行一份 `train` / `eval` / `all`；`PAR` 控制该批内部并行，不要另开第二批写同一组目录。

两个硬性顺序（`train` 内部已自动处理，手动拆跑时必须遵守）：

1. **12 个 joint 全部完成后才能跑 84 个后续臂**：后续臂的 checkpoint 校验（`validate_source_checkpoint`）要求同折同种子 joint 的 `epoch=checkpoint_epoch=last_epoch=30`，中断的 joint 末轮会被拒绝；
2. **96 格训练全部完成后才能开始整批评估**：`eval` 会先检查全部训练格的完成标记与产物；`evaluate.py` 只接受完整 30 轮的 `last.pt`。§5 的内部 `_evalcell` 仅用于已完成 joint 的单格试跑。

拆开跑也行：

```bash
bash scripts/run_cloud.sh check
nohup bash scripts/run_cloud.sh train > logs/train.log 2>&1 &
# 训练 96/96 完成后：
nohup bash scripts/run_cloud.sh eval > logs/eval.log 2>&1 &
```

并行度用环境变量控制：`PAR=2 bash scripts/run_cloud.sh train`（默认 2，见 §6）。

## 6. 并行与两个 GPU 怎么选

### 先回答：脚本可以并行吗？

**可以并行，但不承诺逐位一致。**

- 每格是独立进程，有自己的固定种子、模型、采样器和输出目录，共享的特征缓存只读；并行不会让不同格共享训练状态。
- `seed_everything` 保留 `cudnn.deterministic=True` 与 `benchmark=False`；脚本在 Python 启动前默认导出 `CUBLAS_WORKSPACE_CONFIG=:16:8`，按 [PyTorch 2.6 LSTM 文档](https://docs.pytorch.org/docs/2.6/generated/torch.nn.LSTM.html) 处理 CUDA 10.2+ 的已知 RNN 非确定性要求。已有环境变量设置会保留，整批应使用一致的设置。
- 这些设置不等于实际重复性验证。GPU、驱动、torch/CUDA/cuDNN 版本及并行度都会影响运行环境；2026-10-13 只跑了一轮全批（未重复训练），所以不能声称已经验证串行与并行逐位一致。
- 整批最好固定同一种 GPU 和软件环境。跨 T4/A10 或不同软件版本不保证逐位一致；是否需要重复性试验须在正式训练前决定，不事后改协议。

### T4 vs A10（价格：T4 1.2、A10 3.3 机时/小时）

| | T4（16GB / 8 核） | A10（24GB / 20 核） |
| --- | --- | --- |
| 价格 | 1.2 机时/小时 | 3.3 机时/小时 |
| 起步并行数 | 单格 PAR=1，整批先试 2 | 单格 PAR=1，整批先试 2 |
| 后续调整 | 监测资源后决定是否加到 3 | 监测资源后决定是否加到 3 |
| 单格显存、耗时、总墙钟时间 | 2026-10-13 实测（PAR=3）：单格 142–1295 s，3 个训练进程合计显存约 1.0 GB，整批墙钟约 7 小时 11 分 | 未实测 |

**T4 实测（2026-10-13 全批，并行度 3，来源 `logs/cloud_all.log`）**：单格训练耗时（每臂 12 格均值）
`adabn` 142 s、`source_continue` 438 s、`ce_K116` 740 s、`ce_K38` 763 s、`ce_K19` 767 s、
`mmd_marginal` 777 s、`joint` 1246 s、`ce_mmd` 1295 s；单份评估 7–32 s。
07:48:17 启动，训练 96/96 于 14:43:19 收尾（6 小时 55 分），评估 108/108 于 14:58:52 收尾（再 15 分）。

**选择依据**：先用第一个完整 joint 的“耗时 N 秒”和 `nvidia-smi` 校准，开目标适配臂后继续观察。多进程会争用同一 GPU、CPU 和内存，PAR 增大不保证线性加速，也不能只按 CPU 核数认定稳定。原先的分钟数、总小时数和“约 10–11 机时”缺少 v7 云端实测依据，不作预算承诺。

测得两种 GPU 的实际整批用时后，再按“用时 × 每小时机时价格”比较费用。暂时不宣称 A10 更省钱，也不承诺 PAR=4 稳定。

## 7. 失败与重跑

- 单格失败不中断同阶段其他格；该阶段失败时不启动下一阶段。失败名单在 `logs/failed_train.txt` / `logs/failed_eval.txt`，`status` 会点名；任务分发失败可能没有单格名单，要同时检查主日志和退出码。
- 重跑同一命令（`train` 或 `eval`）会从头重试未完成格，跳过带 `.complete` 且产物齐全的格，无额外开关。旧脚本或手动入口产生的目录没有该标记，也会归档重跑，不能靠文件存在推断 30 轮已完成。
- `train.py`/`evaluate.py` 拒绝覆盖已有报告或训练目录；脚本自动把残留挪到 `_failed_<时间戳>_<进程号>`，不删除现场。
- 只有一个格反复失败时才去看它的报错与 `_failed_*` 目录里的 `history.csv`（跑到第几轮），不要动别处。
- **云端不要用 `scripts/run_matrix.sh`**：它默认 dry-run（本地预检用），且是顺序单进程，没有 `run_cloud.sh` 的并行与续跑能力。

## 8. 云端不要做的三件事

1. **不要重跑 `selection.py`**：池是冻结的协议组件，`selection.json` 已随仓库带齐；sklearn 版本差异可能给出不同簇，那才是破坏可比性的事。`check` 的 dry-run 会核对 k=19、嵌套池、153/116 口径。
2. **不要提交 `outputs/train/`（2026-10-13 实测 744 MB，含 24 个 `_failed_*` 归档现场）与 `logs/`**（`.gitignore` 已排除）。跑完把 `outputs/eval/`（实测 131 MB，不含权重，108 份 × 4 文件）拉回本地或推回仓库。
3. **不要改判据、预算、配对链、折数或种子**：改了 `configs/stage2.json`，`train.py` 的 `_check_frozen` 直接报错拒绝运行。结果未达标时按 `agents.md` 的零算力错误结构分析走，不临时加臂。
