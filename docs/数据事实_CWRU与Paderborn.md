# 一、源域：CWRU

## 1.1 文件构成 ✅

`rbop_diagnosis_v6/Data/` 的 **161 个 `.mat` 就是 CWRU 官方四个矩阵的完整集合**，文件层面不缺东西。

## 1.2 阶段二的源域口径 ✅

**排 028，四个目录全进源**（`Normal` + `12k_DE` 排 028 + `12k_FE` + `48k_DE`）：

| 目录 | 进源文件数 | 类构成 |
| --- | ---: | --- |
| `Normal` | 4 | N 4 |
| `12k_DE` | 52（60 − 8 个 028） | B 12 / IR 12 / OR 28 |
| `12k_FE` | 45 | B 12 / IR 12 / OR 21 |
| `48k_DE` | 52 | B 12 / IR 12 / OR 28 |
| **合计** | **153** | **N 4 / B 36 / IR 36 / OR 77** |

实测计数（脚本核对，非引用）：

```
源域合计（排 028）: 153 {'B': 36, 'IR': 36, 'N': 4, 'OR': 77}
占比: {'B': '23.5%', 'IR': '23.5%', 'N': '2.6%', 'OR': '50.3%'}
```

**028 档只在 `12k_DE` 里存在**（8 个文件：`B028_0..3`、`IR028_0..3`），`12k_FE` 与 `48k_DE` 里本来就没有 028。排除理由是 **028 是 NTN 轴承**，几何与 7/14/21 mil 的 SKF 不同，跨尺寸实验不可比。文件仍留在 `Data/`，只是不参与枚举。

## 1.3 必须知道的三条后果

1. **类别极度不均衡**：Normal 只占 **2.6%**（4 : 77 ≈ 1 : 19），OR 占 50.3%。v6 的源是 56 文件、OR 占 50%，所以 OR 侧问题不是新增的，但**源域体量从 56 扩到 153 会进一步把 CE 的梯度推向 OR**。
2. **v6 的"源/目标"代码结构整体失效**：`dataset.py` 的 `SOURCE_DATASETS = (Normal, 12k_DE)` 与 `TARGET_DATASETS = (12k_FE, 48k_DE)`、`target_split_v6()`、`DEFAULT_SELECTION_PATH` 指向的冻结标注池全部不再成立——`12k_FE` 与 `48k_DE` 从目标域变成源域，`selection.json` 里那份池/测试列表对 CWRU 内部不再有任何对象。四折文件级划分要重新在 153 个文件上做（`split_source_files` 的 `n_folds=4` 断言会直接炸）。
3. **源域自己变成多域**：四个来源的台架、传感器位置、采样率、批次都不同（`12k_DE` 与 `48k_DE` 是不同批次，相关系数 ~0.02）。这是好事（源域内差异变大，迁移方法发挥空间比 v6 大），但代价是**"源域内差异"与"源→目标差异"混在一起**，报告时必须能分开归因。

## 1.4 源域四折的实际效果

153 文件按类四折（`split_seed=0`）后：

- **Normal 只有 4 个文件 → 每折验证集只有 1 个 Normal 文件**（双通道合计 238–474 窗：`Normal_0.mat` 是半长度文件，仅 119 窗/通道，其余 236–237 窗/通道——❗旧版写"约 235 窗"未区分半长度文件）；
- OR 77 → 每折约 19 个。

CWRU 的 Normal 只有 4 段（官网 97/98/99/100.mat），这是**数据本身的限制，不是划分的问题**。源域 Normal 的验证指标方差天然很大。

## 1.5 v6 已识别的两个稀疏证据层现在落进源域

`48k_DE` 的 `OR014@6_0`（仅 119 窗，半长度族）、`12k_FE` 的 `OR@14@6` / `OR@21@6`（在 `12k_FE` 内各仅 1 个文件；`12k_DE` 与 `48k_DE` 里同层各有 4 个，❗旧版写"全来源各仅 1 个"错）——它们此前是"目标域的薄层"，现在是"源域的训练证据"，四折时会在某一折的验证集里单独出现 1 个文件，逐折指标会抖。

## 1.6 v6 起点权重不可直接复用

v6 的 12 个 `joint` 权重是在 **56 文件**（`Normal` + `12k_DE`）上训的；阶段二源域是 153 文件。分类头结构不变（都是 4 类），所以权重可当**初始化**，但**不能当阶段二的 `joint` 基线**——基线必须在 153 文件上重训。

## 2.4 文件与通道结构（已实测）

- **下载**：32 个 `.rar`，每个 **151.7–178.0 MiB**（中位 157.2 MiB），合计 **5,357,708,539 字节 = 5.36 GB**
- **解包后是两层**（❗方案 v1 初稿写的三层是错的）：`<bearing>/<工况>_<bearing>_<rep>.mat`，例 `K001/N15_M07_F04_K001_4.mat`
- **每个 `.rar` 里除 80 个 `.mat` 还含两个 PDF**：`<bearing>.pdf`（官方事实表，约 40 KB）与 `measuring_log_<bearing>.pdf`（测量日志，约 136 KB）
- **解包后单轴承 0.65 GiB**（80 × 8.32 MiB），**全量约 20.8 GiB**
- **记录总数**：32 × 4 × 20 = **2560** 个测量（每个 4 s）

`.mat` 顶层键就是文件名词干，含 `Info` / `X` / `Y` / `Description` 四个字段，实测结构：

| 字段 | 内容 |
| --- | --- |
| `Y` | **通道列表**（长度 7 的 struct 数组，每项含 `.Name` 与 `.Data`）—— 取数入口 |
| `X` | 低采样率通道，每项带 `Raster` 标签：`Mech_4kHz` / `HostService` / `Temp_1Hz` |
| `Info` | `MeasurementID`、`RevisionMajor/Minor` |
| `Description` | `General.DateTime`（如 `17.09.2015 19:34:44`）、`Measurement.Length=4`、`Start/StopTimestamp` |

`Y` 里的 7 个通道（实测样本数）：

| 通道 | 样本数 | 采样率 | 阶段二是否用 |
| --- | ---: | ---: | --- |
| `vibration_1`（轴承座加速度，单轴压电） | **256,001**（实测全量范围 249,940–299,038，众数 256,001） | **64 kHz** | ✅ **唯一入模通道** |
| `phase_current_1` / `phase_current_2`（电机相电流） | 256,001 | 64 kHz | ❌（PU 的原始主题是电流诊断） |
| `force` / `speed` / `torque` | 16,001 | 4 kHz | ❌ 不进模型；`speed` 作**转速真值**用于物理校验 |
| `temp_2_bearing_module`（轴承模块油温） | 5 | 1 Hz | ❌ |

**PU 是单加速度计数据集**：整台设备只有一个加速度测点，没有 CWRU 那种 DE/FE 双测点。

**工况真值在文件里，不必靠文件名猜**（实测 `N15_M07_F10_K001_1.mat`）：`speed` = 1499.59 rpm（名义 1500）、`force` = 1035.7 N（名义 1000，`F10`）、温度 45.6 °C（原文称实验期 45–50 °C）、`torque` = 1.262 Nm（名义 `M07` = 0.7 Nm，**与名义值不符**，但不进模型）。

⚠️ **`vibration_1` 的单位未在任何官方元数据里标注**。实测 rms 0.4066、峰 ±4.9，量级像 g。**但这不影响本阶段**：v6 的 `logspec512` 是**逐窗跨频标准化**（`_shape_std`，窗口内 z-score），整体增益差（单位/灵敏度差异）会被直接消掉，只剩谱形差异。这是跨设备能成立的关键前提之一，论文里要写明。

## 2.5 规模换算（全量实测，2560 个文件）

实测 `vibration_1` 长度为 **249,940–299,038 点**（众数 256,001，约占四成；❗旧版写的 255,999–262,172 是 P0 三个轴承时的范围，未随全量更新——262,172 点最多切 96 窗，与同段“窗数长尾到 109”直接矛盾，109 窗需要约 29.8 万点），**窗数不是固定值**：全量实测范围 **91–109，众数 93**（≥97 窗的长尾文件共 64 个）。

```
每条记录   4 s × 64 kHz              ≈ 256,001 点（实测 249,940–299,038，众数 256,001）
降采样     × 3/16                    ≈  48,001 点 @ 12 kHz
切窗       // 512                     = 91–109 窗（众数 93，末尾不足一窗丢弃）
每轴承     4 工况 × 20 次 × ~93.2 窗  ≈   7,461 窗
全量       32 × 7,461                = 238,752 窗（实测）
```

**实测总计：32 个轴承、2560 个文件、238,752 个窗。**

逐轴承窗数分布差异较大（下表取众数占比高的几个）：

| 轴承 | 窗数分布 |
| --- | --- |
| K001 | `{93: 65, 94: 13, 95: 2}` |
| KI01 | `{93: 63, 94: 17}` |
| KA03 | `{93: 66, 94: 3, 95: 2, 96: 1, 99: 1, 101: 4, 102: 2, 103: 1}` |
| KI16 | `{93: 69, 94: 3, 95: 2, 100: 1, 101: 2, 105: 2, 109: 1}` |

❗**初稿写的“窗数 93–96”是错的**——那是只看 3 个轴承得出的。真实分布长尾到 109（❗初稿的原始长度范围 255,999–262,172 同源同错，实测为 249,940–299,038）。

特征层体量：`238,752 × 256 维 × float32 = 245 MB` —— **比 20.8 GiB 的原始数据小两个数量级**，所以特征缓存（`.npy`）完全可行，不必反复解 `.mat`。

对照 CWRU 源域：153 文件 × DE/FE 双通道（两通道是独立单通道样本，v6 源训练即沿样本维合并，experiment.py:76）× 约 235 窗/通道 ≈ **68,516 窗**（实测）。**目标域（全 32 轴承 238,752 窗）是源域的 3.5 倍；主口径 29 轴承 216,350 窗是源域的 3.2 倍**（❗旧版写“36,000 窗 / 6.6 倍”是漏算双通道）。

## 2.6 已知缺陷与坑（写进冻结记录，不静默处理）

1. **官方 `KA08.rar` 里的 `N15_M01_F10_KA08_2.mat` 是坏的** ✅：文件被截断并补零，`scipy.loadmat` 报 `TypeError: Expecting matrix here`。
   ❗**磁盘上看不出来**：文件仍是完整的 8.31 MiB（补零到原大小），所以尺寸校验拦不住它，**只有加载才暴露**。
   后果：`KA08` 实际可用 **79** 个文件（其余轴承均 80）。
   **处理方式已冻结（2026-10 用户确认）：整条丢弃**，不写截断专用读取。单元 `KA08×N15_M01_F10` 聚合时按 **19** 条记录计（全数据集唯一不足 20 条的单元），聚合器的“每单元 20 条”断言必须为此显式开口子。
6. **KA08 截断文件的下游计数**（决策见上）：全数据集可加载记录 = 2,559；主口径 29 轴承 = **2,319 条记录 / 216,350 窗**；**单元级 116 条中 115 个为 20 条记录、`KA08×N15_M01_F10` 为 19 条**。所有聚合器与计数断言按这组数字写死。
2. **节径随厂商变** ✅：FAG 28.55 mm，IBU/MTK 29.05 mm（节径差 1.75%），由此 BPFO 倍数差 **0.53%**（3.0543 vs 3.0706，见 §2.9 表；❗旧版把节径差 1.75% 误写成“BPFO 相差约 1.7%”）。逐轴承的 BPFO/BPFI 必须按型号算，不能用全局常量。
3. **KB23/24/27 的类别是人为指派的**：官方按"主导损伤"把 KB23/KB24 归内圈、KB27 归外圈（PHME16 §7.4）。这是作者决策不是真值，**必须在论文里声明**。
4. **记录级划分会泄漏**：同一轴承的 20 次测量是连续采集，同一轴承的 4 个工况是同一物理件。任何"随机拆记录"都会让近邻泄漏到测试集（与 v6 的"先划分文件再切窗"是同一个问题，只是这里换了一层）。
5. **记录长度不齐**（实测，见 §2.5）：窗数 **91–109**、众数 93（❗旧版此处写“93–96”，与 §2.5 同段已更正的全量范围矛盾，是 P0 阶段旧数残留）。**不影响训练**（无需 v6 那种短记录过滤：最小 91 vs 众数 93，比值 0.98），但做“每条记录权重相等”的聚合时要注意每条记录的窗数不完全相同。

## 2.8 全量通路验证结果（32 个轴承，已完成 ✅）

### 验证 1：形状与口径（全部通过）

**32 个轴承、2560 个文件全部走通** `64 kHz → resample_poly(3,16) → 12 kHz → 512 点窗 → logspec512`：

- 输出形状全部为 `(N,1,256)` float32，无一例外；
- 窗内均值全部在 ±2e-8 量级（浮点噪声），窗内标准差 = 1.0000 —— 与 v6 口径**逐位一致**。

### 验证 2：物理判据 vs 官方标签

原始对数谱里**看不到** BPFO——轴承故障的能量在轴承座共振带上，BPFO 表现为共振的边带（与 PU 原论文用包络谱验证数据一致，PHME16 Fig 6/7）。改用**带通 2000–5000 Hz + Hilbert 包络 + FFT**，指标取"基频及前 5 次谐波处的谱幅均值 / 0–500 Hz 中位谱幅"。

**命中 22/29**（KB 不参与判定）：健康 6/6、外圈 11/12、内圈 5/11。

⚠️ **这个数字必须正确解读**：该判据是**零训练的粗糙启发式**（固定单带、固定 5 次谐波、±2 Hz 容差），**不是分类器**。它对弱损伤（L1/L2 电刻笔、小压痕）本来就会失效，**失效不等于标签错误**。

它真正确立的是两件事：

**(a) 通道 / 采样率 / 几何 / 标签链路全部对**。强损伤轴承的谐波比高得毫无争议（1500 rpm 中位）：

| 轴承 | 官方类别 | 来源 | 严重度 | BPFO 比 | BPFI 比 |

## 2.9 6203 特征频率

`BPFO = (n/2)·f_n·(1 − d/D)`，`BPFI = (n/2)·f_n·(1 + d/D)`；6203 为 8 球、球径 6.75 mm、接触角 0。

| 节径 D | BPFO 倍数 | BPFI 倍数 |
| ---: | ---: | ---: |
| 29.05 mm（IBU/MTK） | 3.071 | 4.929 |
| 28.55 mm（FAG） | 3.054 | 4.946 |

与 PU 原文一致性（PHME16 Fig 6/7，`f_n = 25 Hz` 时 `f_o = 76.25 Hz`、`f_i = 123.3 Hz`）：`f_i` 与本表逐厂商计算一致（123.24/123.64 vs 123.3）；`f_o` 对 **FAG** 基本一致（76.36 vs 76.25，差 0.14%），对 **IBU/MTK** 差 0.67%（76.76 vs 76.25）——论文图 6 的示例轴承 KA04 恰是 FAG。本表周期数按 76.25 Hz（论文口径）计算；§2.8 验证 3 与方案 §3.2 的“周期/窗”按 3.071 倍数（IBU/MTK 口径）计算，两者差 0.7%，引用时统一标注来源。
